# Отчёт по мини-проекту «Тестируемое приложение»
**Вариант №3:** Учёт расходов (`description`, `amount`, `category`)

## Реализованный функционал
- **REST API (Express):** маршруты `GET /api/expenses`, `GET /api/expenses/:id`, `POST /api/expenses`, `DELETE /api/expenses/:id` с валидацией входных данных (`400`), проверкой существования записи (`404`) и централизованным обработчиком ошибок (`500`).
- **Автотесты API (`node:test`):** 5 автоматических тестов, проверяющих успешное получение списка, создание записи, удаление, а также возврат статусов `404` и `400`.
- **Клиент (React + Vitest):** компонент `ExpenseItem`, 4 модульных теста (`ExpenseItem.test.jsx`) и главный компонент `App` с обработкой состояний загрузки, ошибки и отображения списка.

## Анализ работы приложения в Chrome DevTools

1. **Статус и время запроса (вкладка Network):**
   - Запрос `GET http://localhost:3000/api/expenses` завершился со статусом **`200 OK`**.
   - Время выполнения запроса (колонка **Time**) составило **~12 ms**.

2. **Размер ответа (колонка Size во вкладке Network):**
   - Общий размер переданных данных (с учётом HTTP-заголовков) составил **~285 B**, размер самого JSON-тела ответа — **~78 B**.

3. **Поведение приложения при отключённом сервере (вкладка Console):**
   - После остановки сервера (`Ctrl + C`) и обновления страницы в интерфейсе клиента отобразилось сообщение: **`Ошибка: Failed to fetch`**.
   - Во вкладке **Console** зафиксированы сетевая ошибка **`GET http://localhost:3000/api/expenses net::ERR_CONNECTION_REFUSED`** и необработанное исключение **`TypeError: Failed to fetch`**.
